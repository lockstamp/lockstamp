What it catches

The holes AI builders leave open

These are the mistakes behind the real leaks. Every attack we report was actually tried on a private copy, not guessed from your settings.

Row Level Security off

Tables anyone can read

Your app's public key is visible in your website's code. If a table has no access rules, anyone holding that key can read, change or delete every row.

select * from profilesPossible
alter table profiles enable row level securityBlocked

Open rules

Users reading each other's data

A rule like using (true) lets every user see every other user's rows.

Role columns

Making yourself an admin

If users can edit their own profile, they can often change their own role too.

Billing tables

Free paid plans

Users who can write to subscriptions can give themselves the top plan.

Keys in your database

Secret keys inside database functions

A service_role or API key written into a database function sits in plain text in your database and its backups. We flag those. (This check doesn't see your app's code.)

Back doors

Views and functions that skip your rules

A view or database function can run with full permissions and hand out data your rules protect, like a helper that returns every user's email to anyone who asks.

        FAQ

        Questions people ask before running it

        Is the query safe to run on my database?

        Yes. It only reads your database's structure: tables, columns, access rules and functions. It doesn't read any rows, doesn't change anything, and doesn't need a password. You can read every line before you run it.

        Does my data get uploaded anywhere?

        No. The check runs inside this browser tab. What you paste is never sent to a server, and closing the tab deletes it.

        Which apps does it work with?

        Any app that uses Supabase for its database, including apps built with Lovable (on Lovable Cloud or your own Supabase), Bolt, Replit, v0 and Cursor.

        What do I do with fix.sql?

        Read it, then run it in the same SQL editor (or add it as a migration). Afterwards, try your app's main features while logged in as a normal user.

        Will the fix break my app?

        It changes who can see what, which is the point: a feature that showed other users' private data will stop doing that. Rules for data that might be meant to be public (like reviews or product listings) are left for you to decide.
